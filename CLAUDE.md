# Академія чарівних світів — правила проекта

Браузерная 3D-игра для ребёнка 6–7 лет (Three.js + TypeScript + Vite, PWA). Обзор и команды — в `README.md`.
Требования, этапы и открытые решения — в `docs/` (начинать с `docs/README.md`).

## Приватность — репозиторий публичный

- **Имя ребёнка никогда не попадает в репозиторий**: ни в код, ни в тексты реплик, ни в документы,
  ни в сообщения коммитов, ни в звуковые файлы. Имя — переменная, которая живёт только в сохранении
  на устройстве.
- Коммиты — только с адресом `noreply` GitHub; он настроен в локальном конфиге репозитория, не менять.
- Защита стоит в хуках `tools/hooks/` (проверяют добавленные строки, имена файлов, сообщение коммита
  и адрес автора). Включить один раз в каждой копии репозитория: `git config core.hooksPath tools/hooks`.
- Список запретных слов лежит вне репозитория: `~/.config/academy/private-words.txt`, по слову или основе
  слова в строке. Без списка хук предупреждает и пропускает. `--no-verify` не использовать.

## Ветки и публикация

- **Вся работа идёт в ветке `dev`.** Отправка `dev` в `origin` ничего не публикует.
- **`main` — это то, что стоит на телефоне ребёнка.** Каждая отправка в `main` пересобирает
  и обновляет игру (`.github/workflows/pages.yml`).
- В `main` попадает только проверенное состояние `dev`, перемоткой (`git merge --ff-only dev`),
  и **только по прямой команде пользователя в текущей сессии**. Разрешение из прошлой сессии не действует.
- «Проверенное» значит: на этом самом коммите прошли `npm test` и `npm run e2e`. Автоматически это делают
  два workflow: `.github/workflows/ci.yml` — на каждую отправку в любую ветку, кроме `main` (в том числе
  в `dev`), и на pull request; `.github/workflows/pages.yml` — на отправку в `main`: тесты, сборка
  и автопрохождение собранной игры идут до публикации, при падении игра на телефоне не обновляется.
- Перед отправкой в `main` убедиться, что публикуемый коммит зелёный:
  `gh run list --workflow ci.yml --branch dev --limit 1 --json headSha,conclusion` — `headSha` равен
  `git rev-parse dev`, `conclusion` равен `success`. Если такого запуска нет, он не завершён или раннер
  не смог выполнить автопрохождение — обязательно локально на этом коммите: `npm test && npm run e2e`.
- Ветка `main` на GitHub защищена (с 2026-11-13): отправка принимается только для коммита, у которого есть
  зелёная проверка `check` из `ci.yml`; правило действует и для владельца, принудительная перезапись и удаление
  ветки запрещены. Отклонённая отправка в `main` значит, что этот коммит не проверен: дождаться `ci.yml` на `dev`,
  а не обходить защиту.
- Прямых коммитов в `main` нет.

## Проверка перед коммитом

    npm test                                         # юнит-тесты (Vitest, src/**/*.test.ts и tools/**/*.test.mjs), около 15 секунд
    npm run build                                    # проверка типов и сборка
    npm run e2e                                      # сборка, автопрохождение мира в размерах телефона и компьютера
                                                     # (компьютер — без сети), проверка вёрстки каждого экрана, запросов,
                                                     # списка моделей и ссылок; около 10 минут с видеокартой
    npm run e2e -- --all-sizes                       # то же в четырёх размерах экрана (так идёт в CI); около 20 минут
    npm run e2e -- --skip-build --mode mobile        # быстрый вариант: уже собранный dist/, только телефон; около 5 минут
    npm run voice:sync -- --check                    # список реплик для записи совпадает с текстами игры (после правки строк —
                                                     # npm run voice:sync и закоммитить voice/phrases.json)
    npm run e2e -- --update-models                   # после добавления или удаления модели: переписать tools/models-used.json
    npm run assets                                   # после правки models-src/: пересобрать public/models (сжатие моделей и текстур)

Автопрохождение обязательно после любого изменения игрового кода. `npm run e2e` завершается с ненулевым кодом,
если в консоли есть ошибка или предупреждение, задание зависло, запрос не удался или ушёл на чужой адрес,
нарушена вёрстка экрана (строка `layout: …`), либо в сборке есть внешняя ссылка; успех — строка `[e2e] PASSED` и код 0. Сервер разработки команде не нужен:
она сама собирает игру и поднимает её на свободном порту начиная с 4183 (`E2E_PORT` задаёт первый порт).
Скриншоты — в `shots-e2e/`. На машине без видеокарты: `E2E_GL=swiftshader Q=0 npm run e2e` — около 10 минут
(с `--all-sizes` — примерно вдвое дольше, не замерено).
Все флаги и переменные окружения: `npm run e2e -- --help`.

Вёрстка: в каждой точке, где прохождение делает скриншот (старт, игра, каждое задание и подсказка, карточки, книга,
родительский раздел), экран измеряется: документ и панели не прокручиваются, каждая панель, кнопка и поле ввода целиком
в окне, кнопки не перекрывают друг друга, облачко реплики не закрывает кнопку, каждая кнопка не меньше 44×44 пикселей.
Нарушение — строка `layout: <размер> <экран>: <элемент> …` и ненулевой код; исключений из правила 44 пикселей в проверке нет.
В каждом виде задания с подсказкой сценарий один раз намеренно ошибается и дожидается «попробуй ещё», подсказки
и показа решения, поэтому адаптивная сложность в нём не растёт; чтобы пройти и измерить задания старших уровней,
размерам задан уровень: `mobile` и `mobile-portrait` — третий, `desktop-tall` — второй, `desktop` — адаптивный
(`E2E_LEVEL=<1|2|3>` задаёт один уровень всем).
Сценарий также дважды закрывает задание с бабочками его кнопкой и возвращается к нему, сверяет навыки до и после
поиска звёзд и по одному разу намеренно ломает разговор и финал (`__game.failNext()`), проверяя, что героиня снова
ходит. Ошибка `scene "…" failed: Error: broken on purpose by __game.failNext()` в консоли в этот момент — ожидаемая;
любая другая ошибка и та же ошибка в другой момент — падение.
Голос в сценарии: после вступления касание кота повторяет его реплику, героиня при этом стоит; после первого осколка
(кнопка карточки нажата, пока персонаж ещё говорит) и после финала реплика кота ждётся вместе с субтитром;
пятая звезда у оленя — и в том же кадре разговор с персонажем, чья цепочка закончена:
приветствие и вопрос задания должны доиграть до конца, облачко не показывает непроизнесённых реплик, касание облачка
перезапускает клип вопроса только после его конца, задание закрывается кнопкой без записи. В конце прохода строка
`lines turned away by the planner: …` перечисляет реплики, отброшенные планировщиком (`src/core/audio.ts`): допустимы
только `go_next` и `t_stars_back`, любая другая — падение, как и открытое задание, о котором планировщик не знает.
Без голоса: проход `desktop-tall` (шаг `walkthrough desktop-tall (no voice)`) играется с громкостью голоса 0 — она
записана в сохранение до загрузки игры, как это делает ползунок родительского раздела. Каждый клип обязан стартовать
с нулевой громкостью, а на каждом кадре задания и подсказки облачко обязано показывать вопрос этого задания (строка
`question: …`); в поиске звёзд вопрос остаётся и после шести секунд, и рядом со счётчиком найденных. В остальных
проходах голос включён, и на кадре подсказки в облачке подсказка. `E2E_MUTE=<0|1>` задаёт одно всем размерам;
с `--all-sizes` шаг `silent walkthrough` падает, если ни один проход не прошёл без голоса.
Кадр подсказки (`hint-<вид>`) в любом проходе снимается, когда показ решения уже на экране: цифры на предметах, числа
над группами, подсвеченные звенья ряда, пульсирующая кнопка или корзина, повтор показа, счёт кота у бабочек. Показа
нет — строка `hint: …` и ненулевой код. У задания «что лишнее» первая ошибка ничего не рисует — там сценарий просто
ждёт конца обеих реплик.
Родительский раздел в сценарии: пример замка читается с экрана; первая цифра ответа и неверное число раздел
не открывают, верный ответ открывает, второе открытие задаёт другой пример. Номер коммита в строке версии сверяется
с `git rev-parse --short HEAD` исходников (строка `version: …`): после нового коммита `--skip-build` со старым `dist/`
падает — нужно пересобрать.
Размеры: `mobile` 844×390 и `desktop` 1280×720 играются всегда; `--all-sizes` добавляет `desktop-tall` 1280×800
и `mobile-portrait` 390×844 — оба workflow запускают именно так. После правки `src/style.css` или разметки — `--all-sizes`.

Проход в размере компьютера идёт без сети (шаг `walkthrough desktop (offline)`; `--mode desktop` — тоже): после первой
загрузки скрипт ждёт, пока сервис-воркер положит в кэш весь свой список, отключает сеть, перезагружает страницу
и проходит весь мир; запрос, который не удался без сети, — ошибка. Остальные проходы идут с сетью.
Новый тип файлов, который запрашивает игра, нужно добавить в `globPatterns` в `vite.config.ts`, иначе этот шаг упадёт.

Модели: `tools/models-used.json` — список файлов из `public/models`, которые страница запросила за оба прохода.
Шаг `models used` в `npm run e2e` падает, если запросы разошлись со списком; `npm test` падает, если в `public/models`
есть файл не из списка или наоборот. После добавления или удаления модели: `npm run e2e -- --update-models`
и закоммитить список. Модель, которую игра не загружает, лежит в `models-unused/` (в сборку не входит).

Сжатие моделей: исходники (`.glb` и текстуры) лежат в `models-src/` и в сборку не входят; `public/models/` целиком пишет
`npm run assets` (`tools/assets.mjs`) и руками не правится. Геометрия и анимации сжаты без потерь (`EXT_meshopt_compression`,
без квантования: `src/core/assets.ts` читает те же `Float32`-массивы, декодер встроен в сборку), текстуры — WebP не больше
1024 по большей стороне (цветовые — с качеством 90, карты нормалей — без потерь), отдельными файлами
`<каталог модели>/tex/<имя>.webp`. Повторный запуск ничего не меняет
(`node tools/assets.mjs --check` — проверка без записи). Порядок при добавлении или замене модели: исходник в `models-src/`
(`tools/pack_hero.mjs` и `tools/usd2glb.py` пишут туда же) → `npm run assets` → `npm run e2e -- --update-models` → закоммитить
`models-src/`, `public/models/` и `tools/models-used.json`. `npm test` (`tools/assets.test.mjs`) падает, если у исходника нет
результата или наоборот, если файл тяжелее 1 МБ, каталог тяжелее 9 МБ, текстура больше 1024, сжатая модель отличается
от исходной хоть одним треугольником, костью или ключом анимации, карта нормалей отличается от исходной хоть одной точкой
или цветовая текстура — сильнее 38 дБ PSNR.

## Язык

- С пользователем — по-русски.
- Голос в игре — украинский; интерфейс и субтитры — украинский и русский, у каждой строки оба текста.
- Комментарии в коде и сообщения коммитов — по-английски, как в существующей истории.

## Параллельная работа

- `src/main.ts` — общий файл почти для любой задачи: до его разбора (`ARCH-05`) в него пишет один
  исполнитель за раз.
- `src/ui/strings.ts`, `src/core/save.ts`, `src/style.css`, `index.html` — тоже общие.
- Агенты, меняющие файлы, работают в отдельных рабочих копиях и не коммитят; коммит делает основная
  сессия после проверки.
- Перед сборкой, установкой пакетов и отправкой в репозиторий проверять параллельные сессии.
- Волновые прогоны (`/checklist-run`) берут команды, порты агентов и общие файлы из
  `.claude/checklist-run/profile.md`.

## Содержание игры

- Никаких штрафов, таймеров ответа и потери наград.
- Никаких внешних ссылок, рекламы, регистрации.
- Модели и звуки — только CC0 или собственные; каждый источник записывается в `CREDITS.md`.
- Сгенерированные изображения (решение Q13) допустимы на условиях: каждый файл записан в `CREDITS.md` — модель,
  сервис, дата, «сгенерировано, передано в общественное достояние по CC0»; изображение просмотрено и принято
  заказчиком; на нём нет узнаваемых чужих персонажей и стилей; сохранение запросов в аккаунте сервиса выключено.
  Генерация платная — только по команде пользователя; ключ лежит вне репозитория, в `~/.config/academy/openrouter.env`.
- Каждая новая произносимая строка должна быть записана голосом до публикации в `main`. Это проверяют `npm test`
  (реплика из `voice/phrases.json` без клипа, записанного ровно с её текста и интонации, — падение) и `npm run e2e`
  (реплика, доставшаяся синтезатору устройства, — ошибка). Запись — `python3 tools/gen_voice.py`: сервис платный,
  запускать только по команде пользователя; ключ лежит вне репозитория, в `~/.config/academy/gemini.env`.
