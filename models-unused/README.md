# Модели, которые игра сейчас не загружает

Здесь лежат файлы моделей, которые раньше были в `public/models`, но ни разу не запрашиваются игрой.
Папка находится вне `public/`, поэтому в сборку (`dist/`) и в кэш для работы без сети её содержимое не попадает.
Файлы не удалены: это те же CC0-наборы, что описаны в `CREDITS.md`, и они могут понадобиться в следующих мирах.

## Почему вынесено

Сервис-воркер при установке скачивает на устройство все файлы из сборки, нужны они игре или нет.
Замер 2026-11-13: из 124 файлов в `public/models` страница за два полных автопрохождения (в размере телефона
и компьютера) запросила 71 — 60 моделей и 11 текстур. Остальные 53 модели (3,4 МБ) только занимали место
в первой загрузке; они перенесены сюда с тем же относительным путём, что был под `public/models/`.

Две модели отсюда — `nature2/Flower4Group.glb` и `nature2/GrassCommonShort.glb` — ссылаются на внешние текстуры
`tex/*`. Текстуры остались в `public/models/nature2/tex/`, потому что ими пользуются загружаемые модели.

## Как вернуть модель в игру

1. Перенести файл обратно с тем же относительным путём:
   `git mv models-unused/<набор>/<файл>.glb public/models/<набор>/<файл>.glb`.
2. Загрузить её в коде игры (иначе она снова окажется неиспользуемой).
3. Запустить `npm run e2e -- --update-models` — команда пройдёт игру в обоих размерах и перепишет
   `tools/models-used.json`, список файлов, которые страница действительно запросила.
4. Закоммитить модель, код и обновлённый список вместе.

Пока модель лежит в `public/models`, но её нет в `tools/models-used.json`, падает `npm test`
(`tools/models-used.test.mjs`); если игра запрашивает не то, что в списке, падает шаг `models used` в `npm run e2e`.

## Как убрать модель из игры

Убрать её загрузку из кода, перенести файл сюда и запустить `npm run e2e -- --update-models`.
