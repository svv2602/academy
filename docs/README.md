## Формат требования

Каждое требование — карточка с постоянным идентификатором. Идентификаторы не переиспользуются
и не перенумеровываются: снятое требование остаётся со статусом «снято».

```
### VOICE-02 — Прерванная реплика завершается сразу
- **Приоритет · объём · этап:** critical · S · Э1
- **Основание:** аудит, `src/core/audio.ts:52` (подтверждено кодом)
- **Требование:** одно проверяемое утверждение.
- **Приёмка:** чем именно это проверяется (тест, команда, сценарий на устройстве).
- **Пишет:** файлы, которые придётся менять. **Зависит от:** идентификаторы.
```

- **Приоритет:** `critical` — без этого игра не выполняет своё назначение или ломается;
  `high` — заметно влияет на качество; `medium` — желательно; `low` — когда-нибудь.
- **Объём:** `S` — меньше дня, `M` — 1–3 дня, `L` — больше трёх дней работы агента.
- **Этап:** `Э0`…`Э5`, см. [20-roadmap.md](20-roadmap.md).
- **Основание** показывает, откуда требование: раздел исходного промпта (`промпт §N`),
  договорённость (`решение 2026-11-13`) или аудит. У аудита всегда помечено,
  **подтверждено кодом** это или **гипотеза**.
- **Пишет** — исходные данные для графа конфликтов: два требования, пишущие в один файл,
  нельзя отдавать разным агентам в одной волне.
- **Состояние** — необязательная строка с датой: что из требования уже сделано и что осталось.
  Требование без этой строки не начато.

## Как раскладывать на чеклисты

1. Один прогон `/checklist-run` — один этап или его связная часть (состав прогонов предложен в
   [20-roadmap.md](20-roadmap.md)). Весь документ в один прогон не помещается и не должен.
2. В манифест прогона (`MANIFEST.md`) переносится поле **«Требование»** дословно, источник — идентификатор.
3. **Гипотеза — не задача.** Требование с пометкой «гипотеза» начинается с фазы замера;
   если замер гипотезу не подтвердил, требование снимается с записью результата.
4. Требования этапа Э5 (миры 2–5) — рамочные. Перед прогоном по каждому миру пишется его
   дизайн-документ `docs/worlds/world-N.md` и согласуется с заказчиком.
5. Открытое решение из [21-open-decisions.md](21-open-decisions.md) блокирует только те требования,
   у которых оно указано в «Зависит от».

## Правила для всех исполнителей

Эти правила действуют всегда, их не нужно повторять в каждом требовании.

- **Имя ребёнка никогда не попадает в репозиторий**: ни в код, ни в тексты реплик, ни в документы,
  ни в сообщения коммитов, ни в звуковые файлы. Репозиторий публичный. Имя — переменная, которая живёт
  только в сохранении на устройстве.
- **Коммиты** — с адресом `noreply` GitHub (настроен в локальном конфиге репозитория).
- **Никаких штрафов**: задания не отнимают награды, не ограничивают время ответа, не «проигрываются».
- **Никаких внешних ссылок, рекламы, регистрации, платных механик.**
- **Голос — украинский.** Интерфейс и субтитры — украинский и русский.
- **Целевое устройство — Samsung S22, Chrome, альбомная ориентация.** Планшет и компьютер — вторичны,
  но должны работать.
- **Отправка в `main` публикует игру** на устройство ребёнка. Правила ветвления — `ARCH-04`.
- **Модели и звуки — только CC0 или собственные**, каждый источник записывается в `CREDITS.md`.
- Агенты не коммитят сами: пишут файлы и отчитываются, коммит делает основная сессия после проверки.
