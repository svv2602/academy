# 14. Архитектура, тесты, процесс — `ARCH-*`

## Как устроено сейчас

```
src/main.ts            681 строка: рендер, уровни качества, загрузка, героиня, кот, персонажи,
                       задания в мире, диалоги, финал, камера, игровой цикл, отладочный объект
src/core/              assets (модели), audio, input, save, util
src/game/              actor, hero, fx, tasks (10 генераторов + отрисовка на панели), quests (5 записей)
src/world/             terrain, scenery, butterflies — всё про первый мир
src/ui/                ui (панели), strings (тексты uk/ru)
tools/                 автопрохождение, замеры, конвейеры моделей и голоса
```

Главная проблема: почти любое изменение игры пишет в `src/main.ts`. Пока это так, задачи нельзя
раздавать агентам параллельно, а второй мир нельзя подключить, не переписав общий код.

### ARCH-01 — Юнит-тесты запускаются одной командой и блокируют публикацию

- **Требование:** `npm test` запускает юнит-тесты; workflow публикации выполняет `npm test` до сборки
  и не публикует игру при падении.
- **Приёмка:** намеренно сломанный тест в пробной ветке останавливает workflow; первые тесты покрывают
  `recordTask`, `levelFor`, `loadSave` (включая перенос сохранения первой версии).
- **Пишет:** `package.json`, `package-lock.json`, `vite.config.ts` или `vitest.config.ts`,
  `.github/workflows/pages.yml`, `src/core/save.test.ts`. **Зависит от:** —.
- **Состояние на 2026-11-13:** выполнено. `npm test` (Vitest) — 28 тестов на `recordTask`, `levelFor`, `loadSave`
  (и на `defaultSave`, `storeSave`, `clearSave`); шаг стоит в `pages.yml` до сборки и в `ci.yml`. Приёмка пройдена
  на GitHub: в пробной ветке с намеренно сломанным тестом `ci.yml` завершился ошибкой на шаге «Unit tests»
  (1 упал, 40 прошли), сборка и автопрохождение не запускались; ветка удалена. Сам `pages.yml` с этим шагом
  впервые выполнится при следующей публикации из `main`.

### ARCH-02 — Автопрохождение — обязательная проверка перед публикацией
- **Приоритет · объём · этап:** critical · M · Э0
- **Основание:** аудит D-17; возможность запуска в CI — гипотеза H-05
- **Требование:** `npm run e2e` собирает игру, поднимает её, проходит весь мир в размерах телефона
  и компьютера и завершается с ошибкой, если есть сообщение об ошибке в консоли, зависшее задание
  или неудавшийся запрос; команда выполняется в workflow публикации, а если в CI нет графики —
  перед каждой отправкой в `main` локально, что записано в `CLAUDE.md`.
- **Приёмка:** намеренная ошибка в коде задания останавливает `npm run e2e` с ненулевым кодом.
- **Пишет:** `tools/shot.mjs`, `package.json`, `.github/workflows/pages.yml`. **Зависит от:** —.
- **Состояние на 2026-11-13:** сделано в коде: `npm run e2e` (`tools/e2e.mjs`) собирает игру, поднимает собранную
  версию, проходит мир в размерах `mobile` и `desktop` и проверяет ссылки в `dist/`; код возврата ненулевой при
  ошибке или предупреждении в консоли, зависшем задании, неудавшемся или внешнем запросе, внешней ссылке. Приёмка
  пройдена мутациями: намеренная ошибка в коде задания останавливает команду. Гипотеза H-05 подтверждена локальным
  замером: с программной отрисовкой (`E2E_GL=swiftshader`, `Q=0`) на 4 ядрах `mobile` — 278 с, `desktop` — 310 с,
  вместе 9,8 мин, без ошибок и предупреждений. Команда стоит в `.github/workflows/pages.yml` перед публикацией
  (на уже собранном `dist/`: публикуется то, что проверено) и в `.github/workflows/ci.yml` (все ветки, кроме `main`,
  и pull request). Первый запуск `ci.yml` на раннере GitHub (ветка `dev`, коммит `d29911c`) прошёл: Chrome 156 на месте,
  `mobile` — 236 с, `desktop` — 260 с, 20–22 кадра на нижнем уровне графики, без ошибок; весь запуск — 8 мин 39 с.
  `pages.yml` с этими шагами впервые выполнится при следующей публикации из `main`. На случай, если раннер
  автопрохождение выполнить не сможет, в `CLAUDE.md` («Ветки и публикация») записан обязательный локальный прогон
  перед отправкой в `main`.

### ARCH-04 — Публикация отделена от разработки
- **Приоритет · объём · этап:** high · S · Э0
- **Основание:** аудит: любая отправка в `main` сразу обновляет игру на устройстве ребёнка
- **Требование:** разработка идёт в ветке `dev`; в `main` попадает только состояние, на котором прошли
  `npm test` и `npm run e2e`; публикация — отдельное осознанное действие по команде заказчика.
- **Приёмка:** в `CLAUDE.md` описан порядок; последние пять публикаций в `main` — слияния из `dev`.
- **Пишет:** `CLAUDE.md`, `.github/workflows/pages.yml`. **Зависит от:** решение Q2.
- **Состояние на 2026-11-13:** ветка `dev` создана, порядок записан в `CLAUDE.md`. Проверки в workflow добавлены:
  `.github/workflows/ci.yml` выполняет `npm test`, сборку и `npm run e2e` на каждую отправку в `dev`,
  `.github/workflows/pages.yml` — те же проверки перед публикацией из `main`; перед отправкой в `main` публикуемый
  коммит должен быть зелёным в `ci.yml` или локально. `ci.yml` на `dev` уже выполнился успешно; `pages.yml`
  выполнится при первой публикации. Ветка `main` на GitHub защищена (решение заказчика
  2026-11-13): отправка принимается только для коммита с зелёной проверкой `check` из `ci.yml`, в том числе
  от владельца; принудительная перезапись и удаление запрещены. Настройка сделана, отклонение непроверенного
  коммита настоящей отправкой не проверялось.
  Осталось: приёмка «последние пять публикаций в `main` — слияния из `dev`» проверяется по истории будущих публикаций.

### ARCH-13 — Локальная защита от попадания имени в коммит
- **Приоритет · объём · этап:** high · S · Э0
- **Основание:** правило приватности; репозиторий публичный
- **Требование:** локальный хук перед коммитом отклоняет коммит, если в добавленных строках или именах
  файлов встречается слово из списка, который хранится вне репозитория.
- **Приёмка:** пробный коммит со словом из списка отклоняется; без списка хук предупреждает и пропускает.
- **Пишет:** `tools/hooks/pre-commit`, `CLAUDE.md` (как включить). **Зависит от:** —.
- **Состояние на 2026-11-13:** выполнено. Хуки `pre-commit` и `commit-msg` (`tools/hooks/`) проверяют
  добавленные строки, имена файлов, сообщение коммита и адрес автора. Проверено пробными коммитами.
  Список слов на каждой машине создаёт заказчик — без него хук только предупреждает.
- **Состояние на 2026-11-14:** список на машине разработки создан, и первая же проверка с ним нашла два дефекта.
  Первый: коммит с двоичным файлом (модель, клип) проходил без проверки текста — `grep` на двоичных данных
  печатает «binary file matches» вместо строк; исправлено ключом `-a`, проверено 14 пробными коммитами
  в отдельной копии (слово в тексте, в сообщении, в имени файла, внутри двоичного файла, рядом с двоичным
  файлом, чистые коммиты). Второй: в `.claude/checklist-run/agent-blocks.md` стоял абсолютный путь основного
  дерева; заменён на `<корень>`. Проверка всей остальной истории, сообщений коммитов, имён файлов и сборки
  совпадений не нашла.
- **История переписана 2026-11-14** по решению заказчика: путь заменён на `<корень>` во всех коммитах,
  где он был. Содержимое остальных файлов, авторы, даты и сообщения коммитов не менялись. Идентификаторы
  коммитов, начиная с пятого, стали другими; ссылки на них в `docs/` обновлены, а в материалах прежних
  прогонов (`development-checklists/`, вне репозитория) остались прежние — таблица соответствия лежит там же.
  Для отправки переписанной ветки `main` принудительная перезапись была разрешена на время одной отправки
  и запрещена снова.

## Правила параллельной работы

- До завершения ARCH-05 файл `src/main.ts` — общий: требования, которые в него пишут, выполняются
  по одному, не в одной волне.
- `src/ui/strings.ts`, `src/core/save.ts`, `src/style.css`, `index.html` — общие всегда: два чеклиста,
  пишущие в один из них, идут в разных волнах.
- Изменение формата сохранения — отдельный чеклист; код, читающий новые поля, — в следующей волне.
- Агенты, меняющие файлы, работают в отдельных рабочих копиях (`worktree`) и не коммитят.
