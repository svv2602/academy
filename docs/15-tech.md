# 15. Производительность, ассеты, надёжность — `TECH-*`

## Как устроено сейчас

- Три уровня качества (`q2` — свечение и тени, `q1` — тени, `q0` — без них); при устойчивых
  менее 34 кадрах уровень снижается сам. Параметр `?q=` фиксирует уровень.
- Трава, цветы и мелочь рисуются только вблизи героини; деревья — экземплярами одной геометрии.
- PWA с автообновлением; в кэш входят `js, css, html, glb, mp3, svg, png, webp` до 4 МБ на файл.
- Модели: исходники — в `models-src/`, в сборку не входят; `public/models/` пишет `npm run assets` — геометрия
  и анимации сжаты без потерь, текстуры — WebP не больше 1024 (`TECH-02`).
- Первая загрузка — 10,6 МБ (до сжатия, 2026-11-14, — 24 МБ).

## Бюджет

Действует для каждого мира. Измеряется в самой тяжёлой точке мира.

| Показатель | Бюджет | Сейчас |

| Кадры на S22, уровень `q1` и выше | не меньше 45 | не измерено; как измерить — [perf.md](perf.md) |

| Первая загрузка: записанный голос (`dist/voice/`) | до 4 МБ (решение 2026-11-16: свой предел, чтобы голос и миры не вытесняли друг друга) | 1,15 МБ (2026-11-16, `ff02067`, до записи Э3) |

## Требования

### TECH-01 — Игра работает без сети после первой загрузки
- **Приоритет · объём · этап:** critical · S · Э1
- **Основание:** промпт §12 (PWA); аудит `vite.config.ts:10` — в кэш не входят `jpg`; поломка — гипотеза H-01
- **Требование:** после одной полной загрузки игра запускается и проходится целиком с отключённой сетью.
- **Приёмка:** сначала замер: автопрохождение в режиме «без сети» после первой загрузки и список
  неудавшихся запросов. Затем то же автопрохождение без единого неудавшегося запроса; оно входит
  в `npm run e2e`.
- **Пишет:** `vite.config.ts`, `tools/shot.mjs`. **Зависит от:** ARCH-02.
- **Состояние на 2026-11-13:** выполнено. Замер (H-01 подтверждена): без сети игра открывалась и проходилась до финала,
  но 21 запрос к 6 текстурам `.jpg` из `public/models/nature2/tex/` не удавался (`net::ERR_INTERNET_DISCONNECTED`) —
  кора, камни, трава и грибы оставались без текстур. В список кэша добавлен `jpg` (`vite.config.ts`). Проход в размере
  компьютера в `npm run e2e` теперь идёт без сети (шаг `walkthrough desktop (offline)`): после первой загрузки скрипт
  ждёт, пока сервис-воркер активен и весь его список лежит в кэше, отключает сеть, перезагружает страницу и проходит
  мир; любой неудавшийся запрос — ошибка. Список кэша: 149 записей (25,2 МБ) → 102 записи (22,2 МБ) вместе с TECH-03.
  На телефоне (режим полёта, запуск с главного экрана) проверяет пользователь после публикации.

### TECH-02 — Ассеты сжаты до бюджета
- **Приоритет · объём · этап:** high · M · Э1
- **Основание:** промпт §12 «сжатие 3D-ресурсов»; измерено: 26 МБ, файлы до 2,7 МБ
- **Требование:** текстуры переведены в сжатый формат с размером по большей стороне не больше 1024,
  геометрия моделей сжата; первая загрузка и размер одного файла укладываются в бюджет; конвейер сжатия —
  команда `npm run assets`, а исходные файлы сохраняются вне сборки.
- **Приёмка:** `du` по `dist/`; скриншоты автопрохождения до и после — без заметной потери качества;
  кадры не ниже прежних.
- **Пишет:** `tools/` (новый скрипт), `public/models/*`, `src/core/assets.ts`, `package.json`,
  `vite.config.ts`. **Зависит от:** ARCH-02, TECH-03.
- **Состояние на 2026-11-14:** выполнено, кроме замера кадров на телефоне. Замер до: `dist/` 24,3 МБ (138 файлов) — модели
  `.glb` 16,8 МБ, отдельные текстуры 5,5 МБ, звук 1,1 МБ, код 0,9 МБ; самый тяжёлый файл 2,7 МБ. Вес моделей — геометрия
  11,2 МБ (набор природы записан без индексов, по три вершины на треугольник), текстуры PNG внутри файлов героини 4,1 МБ,
  анимации 1,0 МБ. Сделано: исходники перенесены в `models-src/` (в сборку не входят), `public/models/` целиком пишет
  `npm run assets` (`tools/assets.mjs`). Геометрия и анимации сжаты `EXT_meshopt_compression` без потерь — без квантования,
  упрощения и пересэмплирования: загрузчик (`src/core/assets.ts`) получает те же `Float32`-массивы, декодер (25 КБ) встроен
  в сборку и работает без сети. Текстуры — WebP не больше 1024 по большей стороне, отдельными файлами
  `<каталог модели>/tex/<имя>.webp`: цветовые — с качеством 90 (альфа-канал без потерь, цвет под прозрачными точками
  сохранён; отличие от исходника 40,8–51 дБ PSNR), карты нормалей — без потерь (WebP с потерями даже при качестве 100
  поворачивал 5 % нормалей одежды героини больше чем на 7°).
  После: `dist/` 10,6 МБ (149 файлов) — `.glb` 5,8 МБ, текстуры 2,8 МБ, звук 1,1 МБ, код 0,9 МБ; самый тяжёлый файл 0,85 МБ
  (код), из моделей — 0,70 МБ. Чем проверено: `du -sb dist`; `npm test` (`tools/assets.test.mjs`: у каждого исходника есть
  результат и наоборот, файл не тяжелее 1 МБ, `public/models` не тяжелее 10 МБ (с TECH-14, 2026-11-16: детская героиня, королева на прежней модели), текстура не больше 1024, каждая сжатая модель
  совпадает с исходной побитно — треугольники, скелеты, ключи анимаций, имена клипов; карты нормалей совпадают с исходными
  поточечно, цветовые текстуры — не хуже 38 дБ PSNR при нетронутом альфа-канале); `npm run e2e -- --all-sizes`, включая
  проход без сети; два запуска `npm run assets` подряд дают одинаковые файлы; кадры автопрохождения до и после
  сопоставлены (все 148 пар — по разнице пикселей, 11 пар — глазами), крупные планы героини, единорога, сундука и замка
  (`tools/closeup.mjs`) сняты на прежних и на сжатых моделях — отличий в размере и положении моделей, листве и героине
  не найдено; лиса, олень и грибной король крупно не сняты — их неизменность подтверждает тест побитного совпадения. Число треугольников и вызовов отрисовки не изменилось
  (в кадре после сбора кристалла: телефон — 535 тыс. и 338, компьютер — 717 тыс. и 363, до и после одинаково); на компьютере
  автопрохождение держит 60 кадров на уровне `q2`, как и раньше. Не проверено: кадры в секунду на S22 и вид текстур
  на экране телефона. Замер на компьютере разработки до и после (`node tools/fps.mjs q=2 q=1`, `node tools/budget.mjs`)
  совпал до числа: 60 кадров на `q2` и `q1`, 963 тыс. треугольников с тенями, 459 вызовов отрисовки, 689 тыс. в кадре. Резерв, если бюджет понадобится
  ужать ещё:
  квантование координат и нормалей (около 2,5 МБ, требует правки всех четырёх путей чтения в `assets.ts`), сжатие анимаций
  с потерями (около 0,4 МБ), карты нормалей с потерями (около 0,6 МБ).
  Дополнение 2026-11-14: бюджет всей сборки закреплён проверкой — шаг `dist size` в `npm run e2e` (`tools/dist-size.mjs`, юнит-тест
  `tools/dist-size.test.mjs`) падает, если `dist/` больше 12 МБ или в нём есть файл больше 1 МБ; идёт в CI в каждом задании прохода.
  Дополнение 2026-11-16 (решение заказчика): голос — свой предел. Шаг падает, если `dist/` без `voice/` больше 12 МБ, `dist/voice/` больше 4 МБ
  или файл больше 1 МБ; печатает вес игры и голоса отдельно. Клипы, которые игра догружает по ходу (банк старой игры, VOICE-07), в сборку не входят.

### TECH-03 — В сборке нет неиспользуемых моделей
- **Приоритет · объём · этап:** medium · S · Э1
- **Основание:** аудит: 113 файлов моделей, в коде около 25 явных ссылок плюс составные имена;
  лишние файлы — гипотеза H-02
- **Требование:** каждый файл в `public/models` загружается хотя бы в одном автопрохождении;
  неиспользуемые перенесены в папку вне сборки.
- **Приёмка:** сначала замер: скрипт сравнивает список файлов со списком запросов за автопрохождение.
  Затем тот же скрипт в `npm test` падает при появлении неиспользуемого файла.
- **Пишет:** `tools/` (новый скрипт), `public/models/*`. **Зависит от:** ARCH-02.
- **Состояние на 2026-11-13:** выполнено. Замер (H-02 подтверждена): из 124 файлов в `public/models` страница за два
  автопрохождения запросила 71 (60 моделей и 11 текстур); 53 модели (3,4 МБ) не запрашивались и перенесены
  в `models-unused/` с тем же относительным путём. `public/models`: 124 → 71 файл; `dist/`: 26 → 23 МБ (154 → 101 файл).
  Список запрошенных файлов хранится в `tools/models-used.json`: шаг `models used` в `npm run e2e` падает, если запросы
  страницы за оба прохода расходятся со списком, а тест `tools/models-used.test.mjs` в `npm test` падает, если
  в `public/models` есть файл не из списка или в списке есть файл, которого нет. После добавления или удаления
  модели список переписывает `npm run e2e -- --update-models`.

### TECH-04 — Уровень качества запоминается
- **Приоритет · объём · этап:** high · S · Э1
- **Основание:** аудит D-12, `src/main.ts:37` (подтверждено кодом)
- **Требование:** игра стартует с уровня качества, на котором закончилась прошлая сессия; раз в десять
  запусков пробует уровень выше; родитель может закрепить уровень в своём разделе.
- **Приёмка:** юнит-тест выбора стартового уровня; после автоснижения и перезагрузки игра стартует
  с пониженного уровня.
- **Пишет:** `src/main.ts`, `src/core/save.ts`, `src/ui/ui.ts`, `src/ui/strings.ts`. **Зависит от:** —.
- **Состояние на 2026-11-14:** выполнено. Стартовый уровень выбирает чистая функция `startTier()` (`src/core/quality.ts`):
  `?q=` (0–2) важнее всего, затем уровень, закреплённый родителем, затем сохранённый; каждый десятый запуск (запуск —
  загрузка страницы) пробует сохранённый уровень на один выше, не выше 2. Сохранение (версия 2, новые поля с умолчаниями:
  `tier`, `launches`, `pinTier`) хранит уровень текущей сессии — при загрузке и сразу после автоснижения; старое
  сохранение без этих полей открывается без потери прогресса (тест `loadSave`). Родительский раздел: строка
  «Якість графіки / Качество графики» — кнопка перебирает «Авто → Висока → Середня → Проста»; закреплённый уровень
  действует сразу, автоснижение его не меняет; `?q=` закрепление перекрывает и сохранённый уровень не трогает.
  Проверено: юнит-тест `quality.test.ts` на все ветки; `npm run e2e` в проверке без `?debug` после автоснижения
  перезагружает страницу — холст сразу после загрузки уже исходного (уровень пониженный).

### TECH-05 — Звук останавливается, когда игра не на экране
- **Приоритет · объём · этап:** high · S · Э1
- **Основание:** аудит D-13, `src/main.ts:432` (подтверждено кодом)
- **Требование:** при скрытии страницы музыка, эффекты и голос приостанавливаются, при возврате —
  возобновляются; планировщик музыки не накапливает пропущенные ноты.
- **Приёмка:** юнит-тест с подменённым состоянием страницы: аудиоконтекст приостановлен и возобновлён;
  на S22 после блокировки экрана звука нет.
- **Пишет:** `src/core/audio.ts`, `src/main.ts`. **Зависит от:** —.
- **Состояние на 2026-11-14:** выполнено в коде; **на S22 после блокировки экрана не проверено — заказчик.**
  `src/core/audio.ts` сам слушает `visibilitychange`: при скрытии — `AudioContext.suspend()`, звучащий клип на паузе
  (не оборван), синтезатор на паузе, эффекты не ставятся; ожидание реплики не завершается, пока страница скрыта
  (страховочные таймеры реплики в фоне не срабатывают и после возврата отсчитывают своё время заново, реплика,
  запрошенная в фоне, начинается при возврате) — цепочки реплик не идут дальше. При возврате — `resume()`, клип
  продолжается с того же места, синтезатор — `resume()`. Планировщик музыки, отставший от часов контекста, продолжает
  с текущего момента и пропущенные ноты не ставит. `main.ts` при скрытии только сохраняет. Проверено: юнит-тесты
  `audio.test.ts` с подменёнными `document` (`hidden`, `visibilitychange`) и `AudioContext`.
- **Проверено на S22 2026-11-15** (сборка `c3808cf`, по USB, без подключённой отладки): игра запущена касанием «Грати», звучит
  (два звуковых потока Chrome — `started`); экран заблокирован — через 3 с оба `stopped`, через 8 с потоков нет. Не
  подтверждено: что звук возвращается после разблокировки (через 3 с после неё потоков ещё не было). Замечание: пока к вкладке
  подключены инструменты отладки Chrome, страница при погасшем экране остаётся «видимой» и звучит — проверять только без них.
- **Проверка заказчика на S22, 2026-11-17, сборка `4ed74cb`:** «ок, замечаний пока нет». Это общий ответ на список
  проверки (`docs/perf.md`, «Проверка заказчика на S22»); по пунктам заказчик не расписывал.

### TECH-07 — Понятное сообщение, если устройство не подходит
- **Приоритет · объём · этап:** medium · S · Э1
- **Основание:** промпт §12 «WebGL с проверкой поддержки WebGL2»
- **Требование:** если WebGL2 недоступен, вместо игры показывается сообщение на выбранном языке
  с советом обновить браузер.
- **Приёмка:** автотест с отключённым WebGL видит сообщение и не видит ошибок в консоли.
- **Пишет:** `src/main.ts`, `src/ui/strings.ts`, `index.html`. **Зависит от:** —.
- **Состояние на 2026-11-14:** выполнено. `src/main.ts` до создания отрисовки спрашивает у отдельного `<canvas>`
  контекст `webgl2`; без него стартовый экран показывает вместо полосы загрузки сообщение (`no_webgl` в
  `src/ui/strings.ts`, украинский и русский, по сохранённому языку; кнопки UA / RU его переключают) с советом обновить
  браузер или открыть игру в другом, а модуль дальше не выполняется: ни отрисовки, ни уровня качества, ни счёта запусков,
  ни одного запроса модели. Сообщение не произносится (решение заказчика) — его нет в `voice/phrases.json`.
  Приёмка — `tools/failures.mjs`, шаг `failure screens` в `npm run e2e` (один раз, с размером `mobile`): Chrome с
  `--disable-webgl` видит сообщение на обоих языках, ошибок и предупреждений в консоли нет, вёрстка в 844×390 и
  390×844 в норме. Ограничение: браузер, который не понимает саму сборку (ES2022), не дойдёт и до проверки.

### TECH-08 — Сбой загрузки не оставляет вечный экран загрузки
- **Приоритет · объём · этап:** high · S · Э1

### TECH-09 — Ассеты мира загружаются при входе в мир
- **Приоритет · объём · этап:** high · M · Э4 (перенесено из Э5 решением 2026-11-16: до хаба)
- **Основание:** промпт §12 «загрузка локаций по мере необходимости»; замер 2026-11-16: игра с одним миром — 10,44 МБ
  из 12, голос — 2,90 МБ из 4, сервис-воркер кладёт в кэш всё сразу — второй мир в эти пределы не входит. Решение Q14.
- **Требование:** при запуске загружаются только общие ассеты и ассеты текущего мира; ассеты другого
  мира загружаются при входе в портал с экраном загрузки; при выходе из мира его ресурсы освобождаются.
  Вес и кэш (Q14): при установке в кэш входят ядро и первый мир — вместе до 12 МБ без голоса и до 4 МБ голоса, как сейчас;
  каждый следующий мир — до 8 МБ моделей и кадров и до 3 МБ голоса; он скачивается в кэш фоном, пока ребёнок играет
  в предыдущем мире, и после этого открывается без сети; у портала мира, который не скачан, без сети кот говорит,
  что нужен интернет, портал остаётся закрытым, игра в остальных мирах продолжается. Файлы мира лежат в своих каталогах
  (`public/models/…`, `public/voice/…`, `public/story/…` по мирам), проверка размера сборки считает предел каждого мира.
- **Приёмка:** список запросов при запуске не содержит файлов других миров; после пяти переходов
  между мирами занятая память не растёт больше чем на 10 % (TECH-15). Автопрохождение: после входа в мир список
  кэша содержит файлы следующего мира, и он открывается без сети; без сети и без кэша портал закрыт, реплика кота
  звучит записанным голосом, героиня ходит. Шаг `dist size` падает, если ядро с первым миром или любой следующий мир
  больше своего предела; юнит-тест проверки на каждое из этих условий. Записан замер: сколько из нынешней сборки —
  ядро и сколько — первый мир.
- **Пишет:** `src/core/assets.ts`, `src/worlds/index.ts`, `vite.config.ts`, `tools/dist-size.mjs`, раскладка
  `public/models`, `public/voice`. **Зависит от:** ARCH-06.
- **Состояние на 2026-11-18 (не закончено):** механизм собран и проверен на пробном мире, в опубликованной игре
  второго мира ещё нет. Сделано: пределы веса считаются по частям сборки — ядро с первым миром и каждый следующий мир
  отдельно, голос мира отдельно от голоса ядра (`tools/dist-size.mjs`); файлы следующего мира не входят в установку,
  перечислены в `worlds.json` и скачиваются в кэш `worlds` фоном, пока играется предыдущий мир
  (`src/core/worldcache.ts`); мир меняется без перезагрузки страницы, ресурсы покинутого мира освобождаются
  (`src/game/travel.ts`, `src/game/scope.ts`); решение «пускать ли в мир» написано отдельным модулем
  (`src/game/gate.ts`). Не сделано: ворота не подключены к смене мира — закрытого портала и реплики кота «нужен
  интернет» в игре нет; замера «пять переходов, память не больше чем на 10 %» нет; игра ещё не читает клипы голоса
  из папки мира. Два условия к воротам, найденные проверкой 2026-11-18: вход по сети должен докачивать мир целиком
  (сам вход кладёт в кэш только те файлы, которые страница успела запросить, и мир остался бы скачанным частично),
  и запуск сразу в мире не из ядра — когда игра начнёт запоминать мир, в котором остановились, — обязан идти через
  те же ворота. Сегодня такой запуск возможен только с `?debug`.
